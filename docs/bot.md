# remindbot — функционал бота

Приватный Telegram-бот команды SMM: напоминает о задачах, собирает подтверждения
и присылает отчёты. Блок-схемы — в [`bot-flow.pdf`](bot-flow.pdf),
кого и как часто тегает бот (с примерами) — в [`tagging.md`](tagging.md).

Обозначения: ✅ — работает, 🕓 — запланировано, ⏸ — сделано, но выключено.

**С 14.11.2026** бот только напоминает, без вопросов о подтверждении и без тегов админа:
- материал на согласование: просьба за сутки и одно напоминание через час (8.2);
- напоминание о публикации за 30 минут (8.3; до 14.11.2026 — за 60 и 30); с 15.11.2026 для
  постов в Telegram — одно сообщение на день за час до первого, с тегом роли «Телеграм» (8.3);
- контент-план: пн 13:00 «заполните план» (раздел 6);
- отчёт продажников: пн, ср, пт в 16:00 «пора заполнить отчёт», без кнопок (раздел 5).

Выключены и включаются в `.env`: вечерний опрос продажников «отправил?»
(`FEATURE_SALES_POLL=true`), «Выложено?» после публикации (`FEATURE_PUBLISH_QUESTIONS=true`)
и, с 15.11.2026, материал ответом на сообщение бота (`FEATURE_MATERIAL_REPLIES=true`, 8.2):
пока он выключен, бот только просит материал и через час напоминает, ответы не разбирает,
а в `/today` и `/week` у материала только «📨 попросил» / «🕓 запросим».
Пока они выключены, в `/today` и `/week` нет блока продажников, а публикация — только
«🕓 впереди» или «🕘 время прошло»: ответы, данные раньше, в отчётах не показываются
(в базе остаются).

## 0. Как люди попадают в бота ✅

1. Админ добавляет бота в чат, суперадмин назначает чату роль (📎 материалы, 🔔 выкладка,
   💼 продажи). Бот здоровается в чате: что он будет там делать, и кнопка **[👋 Начать]**.
   Для людей, пришедших позже, — `/hello@бот` в чате (суперадмин или админ).
2. Человек нажимает «Начать» → открывается личка с ботом → «Начать». Бот отвечает «Готово»,
   писать ему ничего не нужно.
3. Суперадмину приходит карточка нового человека: роль **[⭐ Админ] [💼 Продажник] [👤 Без роли]**
   и **кто он в YouGile** — кнопки с исполнителями из YouGile и **[🚫 Нет в YouGile]**.
4. `/people` (видят суперадмин и админы, менять может только суперадмин; `/chats` — тоже обоим; `/status`, `/help`, `/admins` и вопрос «Для чего этот чат?» — только суперадмину) — все люди: роль и связка с YouGile, внизу — исполнители YouGile, ещё не
   связанные с Telegram. ✏️ открывает карточку человека.

Связанного исполнителя бот **тегает** в напоминаниях («@kseniya, в 11:00 выложить…»), остальных
называет по имени из YouGile без тега. Почту вместо имени бот команде не показывает: если в
YouGile у человека нет имени, пишет «исполнитель». В отчётах (`/today`, `/week`) — имена без тегов.

## 1. Роли

| Роль | Кто | Как получает | Что может |
|---|---|---|---|
| **Суперадмин** | Иван | Telegram ID в `.env` (`SUPERADMIN_TG_ID`) | всё; назначает роли; `/admins`, `/status` |
| **Админ** | Оля | суперадмин назначает в `/admins` | `/today`, `/week`, `/month`; получает итоги |
| **Основной админ** 📌 | Оля | первый админ — автоматически; сменить в `/admins` | его **одного** бот тегает в чатах и называет людям |
| **sales** | продажники | суперадмин назначает в `/people` | получает ежедневный опрос про отчёт |
| **telegram** ✈️ | ведёт Telegram-канал | суперадмин назначает в `/people` | его тегают в сообщении о постах в Telegram на день |
| **Участник** | все остальные | — | бот ему не отвечает (кроме `/whoami`) |

Роль у человека одна. Назначить роль можно только тому, кто сам написал боту
`/start` — Telegram не даёт ботам писать первыми.

## 2. Доступ и приватность ✅

- Человек пишет боту `/start`:
  - админ / суперадмин → приветствие и личное меню команд;
  - остальные → «Это приватный бот команды…», а суперадмину приходит
    уведомление с кнопками **[⭐ Сделать админом] [💼 Сделать sales]**.
- Команды без нужной роли → «Нет доступа.» (и устаревшее меню у человека пропадает).
- Команды в группах игнорируются (кроме `/whoami`).
- Токен бота не попадает в логи; секреты лежат в `secrets/`.

Защита групп ✅: добавить бота в группу может только суперадмин или админ.
Если добавил кто-то другой — бот сразу выходит и предупреждает суперадмина.

## 3. Меню и команды ✅

Кнопок под полем ввода нет — команды в кнопке **«Меню»** слева от поля ввода.
Меню у каждого своё, по роли.

| Команда | Кому | Что делает |
|---|---|---|
| `/start` | всем | регистрация, приветствие, меню |
| `/whoami` | всем | Telegram ID (и ID чата в группе), версия бота |
| `/today` | админы | 📅 сегодня: публикации из YouGile, материал, отчёты продажников |
| `/week` | админы | 📊 неделя с понедельника: что требует внимания, расписание по дням, продажники |
| `/month` | админы | 🗓 месяц (пока заглушка) |
| `/admins` | суперадмин | 🛡 админы (📌 основной) и кандидаты; продажники — в `/people` |
| `/chats` | суперадмин | 💬 групповые чаты и их назначение: 📝 контент / 💼 продажи |
| `/help` | суперадмин | ❓ справка: что умеет бот |
| `/status` | суперадмин | ℹ️ версия, аптайм, база, YouGile, пользователи, групповые чаты |

### `/admins`

```
🛡 Админы
• @nastya — 📌 основной, его тегает бот      [❌ Снять @nastya]
• @olga                                       [📌 Основной] [❌ Снять @olga]

Писали боту:
• @petr                                       [⭐ Админ @petr]

Продажники и все остальные — в /people.
```

При смене роли человеку приходит сообщение, меню обновляется.

### `/status`

```
ℹ️ Статус
Версия: 20261018-020753-dev
Работает: 2h10m5s
База: ✅ доступна
📋 YouGile: сверка 14:35 · публикаций на 7 дней: 31

👥 Пользователей: 6
   админов: 1 · sales: 2 · обычных: 2
   замечены в групповом чате: 4

💬 Групповые чаты: всего 3
   📝 контент: ✅ есть · 💼 продажи: ✅ есть
   без назначения: 1 — см. /chats
```

Строка «без назначения» — только если такие чаты есть. Если бот ни в одном
чате: «💬 Групповые чаты: ❌ бот пока не добавлен ни в один чат».

## 4. Групповые чаты ✅

У каждого чата есть назначение — от него зависит, какие сценарии туда идут:

| Назначение | Что туда приходит |
|---|---|
| 📎 Материалы | «пришли материал» за сутки до поста или рилс и напоминание через час; сюда же присылают материал ответом |
| 🔔 Выкладка | напоминание о публикации за 30 мин; посты в Telegram на день — за час до первого; контент-план по понедельникам в 13:00 |
| 💼 Продажи | напоминание заполнить отчёт пн/ср/пт 16:00 с тегом каждого (без такого чата — в личку) |
| 📝 Контент | прежнее назначение (до 14.11.2026): получает и материалы, и выкладку; новым чатам не предлагается |

Чатов с одним назначением может быть несколько — каждый получает одни и те же сообщения.

Когда бота добавляют в группу, суперадмину приходит «✅ … добавил бота в чат «…».
Для чего этот чат?» с кнопками **[📎 Материалы] [🔔 Выкладка] [💼 Продажи] [Без назначения]**.
Поменять потом — в `/chats`.

Bot API не отдаёт список участников группы. Бот запоминает:
- группы, куда его добавили / откуда удалили;
- людей, которые в группе написали команду, ответили боту, нажали его кнопку,
  вошли или вышли.

Обычные сообщения группы бот не видит (privacy mode Telegram). Чтобы он
замечал всех пишущих — @BotFather → `/setprivacy` → Disable, затем
переподключить бота к группе. Текст сообщений бот не хранит.

## 5. Отчёт продажников (роль sales) ✅ напоминание пн/ср/пт 16:00 · ⏸ вечерний опрос

Пн–Пт. Отчёт продажник отправляет **руководителю в личку**; бот этот
отчёт не видит и верит ответу на кнопках. Сообщения идут **в чат продаж** с
тегом продажника (кнопки может нажать только он); если чата продаж нет — в личку.

```
18:00  💼 @ivan, пора отправить отчёт за сегодня — пришли его руководителю в личку.
18:20  💼 @ivan, отчёт за сегодня отправил руководителю?   [✅ Да] [❌ Нет]   попытка 1 из 2
18:40  то же — тем, кто не ответил «Да»                         попытка 2 из 2
       «Если ещё не отправил — время есть до 20:40, потом нажми «Да»»
20:40  день закрыт → итог всем админам в личку
```

- «Да» → ✅, кнопки исчезают.
- «Нет» → ❌, в сообщении остаётся кнопка **[✅ Отправил]** до закрытия дня.
- «Да» окончательное: «Нет» под старым вопросом его не отменяет.
- Не ответил → кнопки на вопросах работают до 20:40; после — «⚠️ нет ответа».
- Нажатие после 20:40 → «Время для ответа вышло — напиши руководителю».
- Если бот был выключен в 18:00 — день начнётся сразу после запуска (не позже 21:00).

Итог админам (проблемы сверху):

```
💼 Отчёты продажников за пн 20.10
@olga — ⚠️ нет ответа (2 попытки)
@petr — ❌ не отправил · ответ с 2-й попытки
@ivan — ✅ отправил · с 1-й попытки
```

В `/today` у админов — текущие статусы: 🕓 попрошу в 18:00 · 📨 попросил ·
⏳ ждём ответа · ✅ · ❌ · ⚠️; в выходные — «отчёт не нужен».

## 6. Контент-план на неделю ✅ только пн 13:00, без тега админа

Каждый понедельник, в чат 📝 контента:

```
13:00  🗓 Напоминание: заполните, пожалуйста, контент-план на неделю в YouGile.
18:00  🗓 @nastya, проверь, пожалуйста, контент-план на неделю и утверди его.
```

Тегается только основной админ. Если бот выключен в это время — сообщение пропускается.

## 7. Тихие часы ✅

С **22:00 до 06:00** бот не шлёт ничего по расписанию: такие отправки
переносятся на 06:00 (до 14.11.2026 было до 09:00). Действует для всех сценариев, включая будущие.

## 7.1 Тестовый режим ✅

Для проверки бота на проде, не трогая команду: в `.env` задаётся
`TEST_RECIPIENT_TG_ID=<Telegram ID>` — один или несколько через запятую
(`111111111,222222222`), бот перезапускается. Каждый тестовый получатель получает свою
копию каждого сообщения. Пока режим включён:

| Уведомление | Куда обычно | Куда в тестовом режиме |
|---|---|---|
| Опрос продажников 18:00 / 18:20 / 18:40 | продажникам, в чат продаж или в личку | каждому тестовому получателю в личку — он сам в роли продажника, у каждого свой вопрос и свои кнопки |
| Итог по продажникам 20:40 | всем админам в личку | каждому тестовому получателю |
| Контент-план, пн 13:00 и 18:00 | в чат контента | каждому тестовому получателю в личку |
| Публикации из YouGile (8.2, 8.3) | в чат контента | каждому тестовому получателю в личку; материал можно прислать ответом там же. Кнопки «Выложено?» общие на задачу: ответ одного засчитывается для всех |

- Каждое такое сообщение начинается с 🧪.
- Расписание и тихие часы — как обычно.
- Не перенаправляются: ответы на команды и уведомления суперадмину
  (новый человек написал /start, бота добавили в группу).
- В `/status` строка «🧪 Тестовый режим: уведомления по расписанию получают только …».
- Новые сценарии тоже должны идти через тестовый режим: отправка по расписанию —
  через `notify`, адресаты — через `contentChats` / `salesUsers` / `adminIDs`
  (`internal/telegram/testmode.go`).
- Выключить: стереть значение и перезапустить бота.

## 8. Публикации из YouGile ✅

### 8.1 Задачи из YouGile ✅
Раз в 30 минут с 05:00 до 23:00 (ночью YouGile не опрашивается) бот копирует к себе
задачи доски «ПУБЛИКАЦИИ ВСЕГО» проекта «ИНСАЙТ» со временем публикации от вчера до
+8 дней: тип, название, время, исполнители. Правки в YouGile доходят до бота за ≤30 минут.
Нужен API-ключ YouGile (`secrets/yougile_api_key`); без него сценарии 8.2–8.3 выключены.

- **Время публикации** — начало слота в календаре задачи (`deadline.startDate`),
  округлённое до минуты: YouGile часто хранит 09:00 как 08:59:59.
- **Ответственный** — исполнитель задачи в YouGile. Если исполнителя нет (у всех задач
  телеграма и у части сторис), сообщения адресуются **основному админу** 📌 с тегом.
  Автор задачи не учитывается.
- **Перенесли** задачу — напоминания строятся заново (полученный материал и ответ
  «выложено» сохраняются). **Удалили, убрали в архив, перенесли в другую колонку** —
  напоминания прекращаются. **Сменили исполнителя** — дальше пишется новый.

> **Связка YouGile ↔ Telegram — отложена** (решение 21.10.2026). В YouGile у людей нет
> Telegram, поэтому сейчас бот называет исполнителя по имени из YouGile **без тега**,
> а нажать кнопки и прислать материал может любой в чате. В базе для связки уже есть
> колонка `yougile_users.tg_id`; осталось сделать команду для суперадмина (например,
> `/people`: человек из YouGile ↔ тот, кто написал боту /start) и тегать по ней, а кнопки
> «Выложено?» разрешить только исполнителю и админам. Пока идёт тестовый режим, всё
> уходит Оле, и связка не нужна.

Типы задач — по колонкам доски:

| Тип | Колонка YouGile | Материал за сутки (8.2) | Напоминания о публикации (8.3) |
|---|---|---|---|
| Пост | ПОСТЫ | ✅ | ✅ |
| Рилс | РИЛСЫ | ✅ | ✅ |
| Сторис | СТОРИС | — | ✅ |
| Телеграм | ТЕЛЕГРАМ | — | ✅ |

Остальные колонки доски бот не читает. Типы и их правила — в коде; какая колонка
какому типу соответствует — в таблице `task_type_columns`: если колонку переименуют
или заведут новую, правится строка в базе, без новой версии бота.

**Только чтение:** бот ничего не меняет в YouGile — ни задачи, ни статусы;
ответы людей хранятся только в базе бота.

### 8.2 Материал на согласование (пост, рилс) — за сутки, в чат контента ✅ · ⏸ ответы
```
T−24ч       📎 Катя, завтра в 15:00 пост «Афиши». Пришли готовый согласованный материал.
            💡 Не забудь про сторис и обложку.
+1 ч        📎 Катя, напоминание: пришли материал для поста «Афиши» (вт 15:00).
```
Так — пока `FEATURE_MATERIAL_REPLIES` выключен (с 15.11.2026): напоминание через час идёт
всегда, ответы бот не разбирает. Ниже — как работает, когда он включён: в просьбе
добавляется «— файл или ссылку — ответом на это сообщение», напоминание — только если не
прислали.
- Больше бот не пишет и админа не тегает. Не прислали к публикации — в `/today` и
  `/week` «⚠️ не прислали».
- Строка 💡 — только информация: материал для сторис бот не ждёт и о нём не напоминает.
- Засчитывается **файл** (фото, видео, документ, GIF, аудио) **или ссылка**, присланные
  **ответом (reply)** на любое сообщение бота по этой задаче — так админ видит материал.
  На простой текст в ответ на 📎 бот отвечает «Нужен файл или ссылка». Ответ на 🔔 или
  «Выложено?» засчитывается, только если в нём файл или ссылка и публикация ещё не
  наступила; текст в ответ на них бот не трогает. Прислать может любой.
- Материал уже получен → на новый файл бот отвечает «✅ Материал уже получен», на
  текст вроде «ок, спасибо» — молчит.
- Получен → «✅ Материал для поста «Афиши» получен от …», напоминания прекращаются.
  Альбом засчитывается по первому сообщению.
- Если «за сутки» выпадает на субботу или воскресенье — запрос уходит в **пятницу**
  в то же время (пост в понедельник 15:00 → запрос в пятницу 15:00). Если пятничное
  время попадает в тихие часы (пост в понедельник 22:30), запрос уходит в пятницу в 06:00,
  а не в субботу.
- Материал нужен **за сутки**, поэтому запрос не догоняется: если в нужное время его
  не отправили (бот был выключен, задачу завели в YouGile позже), запроса нет совсем —
  в `/today` «— не запрашивал». Допуск — 30 минут после положенного времени (столько
  задача может ждать сверки с YouGile). С момента публикации — тишина.

### 8.3 Публикация ✅ (напоминания) · ⏸ «Выложено?»
```
T−30        🔔 Катя, в 15:00 выложить пост «Афиши»   (одно напоминание; до 14.11.2026 было ещё за 60)
T+30        ❓ Катя, пост «Афиши» (15:00) выложен?  [✅ Да] [❌ Нет]  · попытка 1 из 4
+30 ×3      повторы, пока нет ответа
+30         «⚠️ нет ответа» — только в отчёт, без сообщения
```
- **Telegram** (с 15.11.2026) — вместо напоминаний за 30 минут одно сообщение на день, за час
  до первого поста:
  ```
  T−60        🔔 @tg, посты в телеграме сегодня:
              • 16:00 «студенческие скидки»
              • 17:00 «рубрика новости на неделе»
              • 18:00 «пост баста»
  ```
  Тегает всех с ролью «Телеграм» (`/people`), нет таких — основного админа. Исполнитель из
  YouGile здесь не учитывается. Пост, добавленный или перенесённый днём, приходит отдельным
  сообщением за час до себя. Бот был выключен — в сообщение попадают посты, которые ещё впереди.
- Спрашиваем **всегда**: отметка «выполнено» в YouGile не учитывается.
- «Да» окончательное. «Нет» → «❌ не выложен», вопросов больше нет, но остаётся кнопка
  [✅ Выложено]. Ответ после «нет ответа» тоже засчитывается.
- Кнопки помнят, про какое время публикации был вопрос. Если задачу с тех пор перенесли
  в YouGile, нажатие ничего не записывает: «↪️ … перенесли на сб 06:00 — спрошу заново».
- Повторы идут ровно через 30 минут: 11:30, 12:00, 12:30 (без сдвига на минуту).
- Напоминания, которые тихие часы сдвигают на время публикации или позже, не отправляются
  (сторис в 05:00 — без 🔔, вопрос в 06:00).
- Бот был выключен — шлёт только последнее подходящее напоминание и только до публикации;
  первый «Выложено?» задаёт, только если опоздал не больше чем на 4 часа.

### 8.4 Отчёты
- ✅ `/today` — сводка по публикациям дня, затем публикации группами — 📱 Сторис,
  🖼 Посты и рилсы, ✈️ Telegram, каждая группа в цитате (полоса слева; цвет у всех один —
  цвет профиля бота, Telegram не даёт боту его менять):
  ```
  <b>13:00</b> 🎬 Рилс «летние коктейли»
  └ Вера, Лена · ⏳ ждём ответа · спросил 2 из 4
  └ 📎 материал: ✅ получен
  ```
  Статусы: ✅ выложено · ❌ не выложено · ⚠️ нет ответа · ⏳ ждём ответа · 🕓 впереди ·
  🔕 не спрашивали (время вопроса прошло, бот не работал). Отдельный блок — материал,
  который запрашивается сегодня (по постам и рилсам на завтра; в пятницу — и на выходные).
- ✅ `/week` — неделя пн–вс **на текущий момент**, не дожидаясь конца недели: сколько
  публикаций по группам (📱 Сторис · 🖼 Посты и рилсы · ✈️ Telegram); «⚠️ Внимание» —
  материал не прислали, без исполнителя (и с вопросами «Выложено?» — не выложено, нет
  ответа); затем неделя по дням, по строке на публикацию: время, тип, название, кто,
  📎 статус материала (и статус публикации, если вопросы включены); отчёты продажников.
- 🕓 Автоотчёт **в воскресенье в 21:00** — та же неделя.
- 🕓 `/month` — файл Excel: «Сводка», «По людям» (ответы с 1-й…4-й попытки),
  «Все задачи» (номер попытки и время ответа).

### 8.5 Запланировано 🕓
- Вебхуки YouGile вместо сверки раз в 30 минут.
- Праздники (сейчас учитываются только суббота и воскресенье).
- Площадки (Instagram / Telegram / VK) с ответственным на каждой; дубли в Telegram.
- Бот — админ Telegram-канала: сам видит выход поста.
- Бэкапы базы.

## 9. Открытые вопросы

- Подтверждать публикацию ссылкой на пост вместо «Да»?
- «Нет ответа» по публикации: тегать ли основного админа сразу или только в отчёт?
- Месячный отчёт: текущий или прошлый месяц; присылать ли 1-го числа автоматически.
- Получает ли суперадмин еженедельный отчёт.
- Какие напоминания по Instagram добавить (директ и комментарии, статистика,
  фотоотчёт после мероприятия…).

## 10. Техническое

| | |
|---|---|
| Язык | Go 1.27 |
| Telegram | `github.com/go-telegram/bot` (long polling) |
| Расписание | River — очередь задач в Postgres (переживает рестарт) |
| База | PostgreSQL 17 (Docker), `pgx/v5` |
| Миграции | goose (`internal/storage/migrations`) + River, применяются при старте |
| YouGile | REST API v2, только GET (`internal/yougile`), ≤40 запросов/мин, повтор на 429 |
| Сбои | Временные ошибки Telegram (5xx, сеть, таймаут, 429) при отправке — до 3 попыток с паузой; при получении сообщений — WARN, не ERROR. Если напоминание о задаче не ушло никуда, шаг откатывается и через минуту отправляется снова. Суперадмину в личку — «не удалось отправить» и «сверка с YouGile не проходит 2 ч» (каждое не чаще раза в 3 ч), и «сверка снова работает». |
| Healthcheck | `GET 127.0.0.1:8081/healthz` |
| Логи | консоль + `LOG_FILE` (`./logs/remindbot.log`, на сервере `/opt/remindbot/logs/`), ротация по размеру: 10 МБ на файл, 5 старых копий. Пишется каждое входящее событие (команда, кнопка, тип вложения — без текста сообщений), каждое отправленное сообщение, шаги сценариев, пропущенные шаги и почему, сверки с YouGile (что появилось, перенесено, пропало) и каждый запрос к YouGile. Токен Telegram, ключ YouGile и пароль базы вырезаются из любой строки лога (`cmd/bot/logging.go`) |

make run       # запуск
make check     # go vet + сборка
make test-db   # интеграционные тесты на базе remindbot_test
