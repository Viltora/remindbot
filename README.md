# remindbot

Приватный Telegram-бот команды SMM: по будням спрашивает продажников, отправили ли
они отчёт, по понедельникам напоминает про контент-план и присылает итоги админам.
По задачам из YouGile напоминает о публикациях (посты, рилсы, сторис, телеграм),
просит материал на согласование и спрашивает, выложено ли.

> Функционал бота: [docs/bot.md](docs/bot.md), блок-схемы: [docs/bot-flow.pdf](docs/bot-flow.pdf).

## Запуск локально

Нужны Go 1.27+ и Docker Desktop.

```bash
make setup        # .env из примера, secrets/ (пароль БД генерируется), Postgres в Docker
# впиши токен тестового бота из @BotFather:
printf '%s' 'ТОКЕН' > secrets/telegram_token
make run          # миграции применяются при старте, затем бот слушает Telegram
```

Отправь боту `/whoami`, впиши свой ID в `.env` → `SUPERADMIN_TG_ID=...`, перезапусти.

| Команда | Что делает |
|---|---|
| `make run` | запустить бота |
| `make check` | `go vet` + сборка |
| `make test-db` | тесты, включая интеграционные на базе `remindbot_test` |
| `make db-up` / `make db-down` | поднять / остановить Postgres (данные в volume сохраняются) |
| `make db-psql` | консоль базы |
| `curl 127.0.0.1:8081/healthz` | healthcheck (`ok`, если база доступна) |

Секреты лежат только в `secrets/` (права 700), в `.env` — пути к ним.
Миграции — `internal/storage/migrations/`, применяются автоматически при старте (goose).

## Сервер

VPS (адрес — в `deploy.local.mk`, см. `deploy.local.mk.example`): Ubuntu 26.04, 1 vCPU, 4 ГБ RAM + 2 ГБ swap. Бот и Postgres
работают в Docker Compose (`Dockerfile`, `docker-compose.yml`), каталог — `/opt/remindbot`.

- Вход только по SSH-ключу, по паролю нельзя (`/etc/ssh/sshd_config.d/00-hardening.conf`).
- Файрвол ufw: открыт только 22/tcp. Входящие подключения боту не нужны (long polling),
  Postgres слушает только `127.0.0.1`.
- Логи контейнеров — не больше 3 файлов по 10 МБ (`/etc/docker/daemon.json`).
- Время на сервере — UTC, расписание бота считается по `BOT_TIMEZONE`.

| Команда | Что делает |
|---|---|
| `make deploy` | выложить код (rsync), пересобрать образ и перезапустить бота; ждёт, пока `/healthz` ответит `ok` |
| `make server-logs` | логи бота (журнал Docker, обнуляется при деплое) |
| `make server-logfile` | лог бота из файла `/opt/remindbot/logs/remindbot.log`, переживает деплой; 10 МБ × до 6 файлов |
| `make server-psql` | консоль базы на сервере |

`make deploy` не трогает на сервере `.env` и `secrets/` — перед первым деплоем их кладут
вручную:

```bash
SERVER=root@<адрес-сервера>   # то же, что в deploy.local.mk
ssh $SERVER 'install -d -m 700 /opt/remindbot/secrets'
# папка для лога: пишет бот под uid 10001
ssh $SERVER 'install -d -o 10001 -g 10001 -m 700 /opt/remindbot/logs'
scp .env $SERVER:/opt/remindbot/.env
scp secrets/telegram_token secrets/yougile_api_key $SERVER:/opt/remindbot/secrets/
# пароль базы на сервере — свой, не локальный; postgres в контейнере читает его под своим uid
ssh $SERVER 'cd /opt/remindbot/secrets && openssl rand -hex 24 > postgres_password && chmod 644 postgres_password'
# бот в контейнере работает под uid 10001 — токен и ключ должны быть доступны ему
ssh $SERVER 'cd /opt/remindbot/secrets && chown 10001:10001 telegram_token yougile_api_key && chmod 600 telegram_token yougile_api_key'
make deploy
```

- Ключ YouGile в контейнере обязателен: compose всегда подключает `secrets/yougile_api_key`.
  Без файла (или без прав для uid 10001) бот не стартует.
- Если в `.env` задан `TEST_RECIPIENT_TG_ID`, бот стартует, только когда этот человек уже есть
  в базе. На пустой базе — сначала очистить переменную, дать человеку написать `/start`, вернуть.

> ⚠️ Один токен — один запущенный бот. Если бот с тем же токеном работает и на сервере, и
> через `make run`, Telegram отвечает `409 Conflict`, а напоминания уходят дважды: у каждого
> экземпляра своя база и своё расписание. Для локальной разработки — отдельный бот в @BotFather.

## Структура

```
cmd/bot/main.go           запуск, конфиг, graceful shutdown
internal/config           env + секреты из файлов, проверка при старте
internal/storage          пул Postgres, миграции, запросы
internal/telegram         бот: хендлеры команд, сценарии, расписание
internal/yougile          клиент YouGile — только GET-запросы
internal/health           GET /healthz
internal/version          версия сборки (ldflags)
```

## Роли

| Роль | Кто | Что может |
|---|---|---|
| Суперадмин | Иван (Telegram ID в конфиге) | всё; роли (`/admins`), назначение чатов (`/chats`), `/status` |
| Админ | Оля | добавлять бота в группы; `/today`, `/week`, `/month`; итог по продажникам в личку |
| Основной админ 📌 | первый админ, сменить в `/admins` | его одного бот тегает в чатах |
| sales | продажники | отвечают на ежедневный опрос про отчёт |
| Участник | все остальные | ничего: бот отвечает только на `/whoami` |

Роль можно дать только тому, кто сам написал боту `/start` — иначе бот не сможет ему писать.

## Приватность

- Добавление в группы в BotFather **не закрываем**: проверка — в коде.
- На событие `my_chat_member` бот смотрит, кто его добавил:
  - суперадмин или админ → чат запоминается, суперадмину приходит вопрос
    «Для чего этот чат?» [📝 Контент] [💼 Продажи] [Без назначения];
  - кто-то другой → бот выходит из чата, суперадмину предупреждение.
- Посторонний на `/start` получает «Это приватный бот команды…», а суперадмину
  приходит уведомление с кнопками ролей. Команды без нужной роли → «Нет доступа.»

## Интеграция с YouGile (опционально)

- **Только чтение.** Бот ничего не меняет в YouGile: только GET-запросы, без создания,
  правки и закрытия задач. У ключа API нет своих ограничений прав — он может всё, что
  может аккаунт, поэтому правило держится в коде (в клиенте нет методов записи), а
  аккаунту «бот» дан доступ только к нужным проектам.
- Проект: **«ИНСАЙТ»** (`25eb0043-16b8-40ed-abf8-e3f2bb24e69d`).
- Источник разовых задач: REST API v2 (`https://yougile.com/api-v2`), ключ — от отдельного
  аккаунта «бот», лежит в `secrets/yougile_api_key` (в env — `YOUGILE_API_KEY_FILE`).
- Что брать: доска «ПУБЛИКАЦИИ ВСЕГО», тип задачи — по колонке (`/task-list?columnId=…`),
  исполнители — `assigned` (часто пусто), срок — `deadline` (мс).
- Типы задач и что бот с ними делает — в коде (`storage.TaskType`: ПОСТЫ, РИЛСЫ, СТОРИС,
  ТЕЛЕГРАМ); какие колонки YouGile им соответствуют — в таблице `task_type_columns`.
- Синхронизация: полная сверка раз в 30 минут с 06:00 до 23:00, ночью запросов нет
  (около 6 запросов за сверку). Вебхуки — позже: им нужен публичный HTTPS.
- Лимит **50 запросов/мин на компанию** (общий с людьми в интерфейсе) → rate limiter ~40/мин,
  ретрай на 429, локальная копия задач.
- Вебхукам нужен публичный HTTPS (домен + Caddy), секретный путь в URL. Подписка на
  вебхук — запрос `POST /webhooks`, то есть запись; бот её не делает, она создаётся один
  раз вручную.
- Связка YouGile ↔ Telegram **отложена**: пока в сообщениях имя исполнителя из YouGile
  без тега, а задачу без исполнителя бот адресует основному админу (см. docs/bot.md, 8.1).
- Код: `internal/yougile` (тест `TestReadOnly` не пустит в клиент запросы на запись),
  сверка — `internal/telegram/yougile_sync.go`, расписание — `tasks_schedule.go`,
  сообщения и ответы — `tasks.go`.
- Ответы «Да / Нет» хранятся только в базе бота, в YouGile не пишутся.
- Регулярные напоминания остаются в боте.
